# 限制、风险与非目标

## 为什么不能“JEI 有配方就全部自动支持”

JEI 知道如何展示配方，却通常不知道：

- 机器从哪一面接收哪种材料；
- 哪个槽是催化剂，是否消耗；
- 机器忙碌时能否继续插入；
- 概率副产物如何向 AE 声明；
- 输出怎样回到网络；
- 专用服务器没有 JEI 时如何工作。

因此 JEI 可以用于生成“只负责发布配方”的聚合样板，但不能替代绑定器路径中的机器适配器，
也不能由本模组接管流体/化学品投料和回收。后者继续由 AE2、Applied Mekanistics 等兼容层负责。

## 第一版明确过滤

- 概率小于 100% 且没有确定性建模策略的输出。
- 结果依赖输入 NBT/组件但配方 API 无法给出确定结果的配方。
- 需要玩家、环境、红石序列或世界方块参与的处理。
- 在绑定器自动投料路径中，会消费或产生流体、气体、化学品但适配器尚未声明支持的配方。
- 输入与输出构成递归复制、可能让 AE 合成规划失稳的配方。
- 超过硬安全上限的 ingredient 变体或目录样板；超出数量计入过滤统计。

单张聚合样板的硬上限为 1,048,576 个具体配方；超出部分会被忽略，不再拆成多张聚合样板。绑定器适配目录仍采用自己的安全上限。
首版尚无游戏内过滤配置界面。

## 0.1.0 执行边界

- 每个绑定同一时间只接收一个在途批次；工厂不会自动按 lane 数提高并发。
- 绑定时点击的方块面是首选输入；该面不能完整接收时，适配器会确定性扫描其他合法物品输入面。
- 原版熔炉不把燃料声明为样板输入，燃料必须预装或由外部物流提供。
- 链接器会抽取绑定机器所有通过输出能力公开的物品并注回同一 AE 网络，包括旧库存、副产物和其他物流产生的输出；绑定即表示玩家授权该网络托管机器输出。
- 目标区块不会被强加载。区块卸载时已接管但尚未投出的输入继续保存在链接器中。
- 解绑或拆除链接器会掉落尚未投入机器的缓冲物品；已投入机器的物品继续归机器库存所有。

## 运行风险

- 数千配方同时刷新可能产生单 tick 尖峰：必须在重载阶段建立索引并做增量 diff。
- 目标机器被外部物流抢占可能令投料失败：`pushPattern` 必须允许返回失败并稍后重试。
- ME 存储已满时输出保留在机器内并持续等待；应通过诊断指标区分“机器未完成”和“网络无可用容量”。
- 网络权限改变后旧绑定不能继续操作：每次重要操作都重新服务端校验。
- 模组升级可能改变机器类或 RecipeType：绑定记录含 schema 与目标类型指纹，失败时安全离线。
